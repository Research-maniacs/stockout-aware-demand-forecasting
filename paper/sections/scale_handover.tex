\section{Development Runs: Sample Versus Population}
\label{sec:scale}

Table~\ref{tab:scale} compares the two standalone Phase~0--4 runs. Run~S tuned hyperparameters fully on 5,000 series; run~P used the fast setting on all 50,000 series. The overall donor share is almost the same in both runs, which suggests that the stratified sample preserves donor availability. Run~P has a lower q50 tuning WAPE for all three mechanisms and a longer runtime. Because the runs differ in tuning mode as well as size, neither difference can be attributed to scale, and the runtimes are not a scaling benchmark. All values in this section come from the tuning window, not the final week. Fit-period donor days outnumber training rows because the first week of history only feeds lag features.

\section{Run~E's Own Phase~0--4 Stage}
\label{sec:handover}

Run~E did not reuse run~S. It executed its own Phase~0--4 stage in the same kernel as its later phases, and its prerequisite audit selected that output (Table~\ref{tab:handover}). At full stored precision its q50 tuning WAPEs equal those of run~S for all three mechanisms, which is consistent with a deterministic pipeline applied to the same data, seed, and sampling rule. The two runs still differ in timestamps, pandas version (3.0.2 in run~S, 2.3.3 in run~E), and file hashes, so we treat them as separate evidence. The Phase~0--4 stage of run~E recorded \texttt{FAST\_MODE=false}; its later phases recorded \texttt{FAST\_MODE=true} and \texttt{RUN\_MODE=FAST}, which selects 200 bootstrap replicates.
